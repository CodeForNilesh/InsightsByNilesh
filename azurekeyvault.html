Azure Key Vault Explained

Azure Key Vault is a secure cloud service for storing secrets, encryption keys, and certificates without hardcoding sensitive values in applications.

Azure Key Vault helps organizations protect sensitive information in a centralized, governed, and auditable place.

It works closely with Azure Active Directory and supports access control through either Access Policies or Azure RBAC.

🔐 What is Azure Key Vault?

Secrets

Store passwords, connection strings, API keys, and other confidential values safely.

Keys

Manage encryption keys used to protect data and applications.

Certificates

Keep SSL/TLS certificates in one secure, managed location.

In short: Azure Key Vault is a secure, managed vault for secrets, keys, and certificates with fine-grained access control.

🛠 How an Application Talks to Key Vault

  1. App identity is created: The app uses a Service Principal or Managed Identity.
  2. Authentication happens: The app authenticates with Azure Active Directory.
  3. Access token is issued: Azure AD returns a short-lived token for the app.
  4. Key Vault is called: The app sends a request using REST APIs or Azure SDKs.
  5. Permissions are validated: Key Vault checks RBAC roles or Access Policies.
  6. Access is granted or denied: The secret, key, or certificate is returned only if permission exists.

⚙️ What Needs to Be Configured

To allow an application to read or manage secrets in Azure Key Vault, you must configure several things carefully. The goal is to give the app a secure identity and then grant only the permissions it truly needs.

  • 1. Identity Create or enable an identity for the application. The most recommended option is a Managed Identity when the app runs inside Azure. If the app is external, create a Service Principal in Azure AD.
  • 2. Key Vault Access Model Decide how access will be granted. You can use Access Policies for a simpler, vault-specific approach, or Azure RBAC for a modern, centralized, and scalable method.
  • 3. Role or Permissions Assign the correct permissions for the required actions. For secrets, common permissions include get, list, set, and delete. For keys and certificates, different permissions may be needed depending on the operation.
  • 4. Network Restrictions If needed, configure firewall rules or private endpoints so that only trusted networks can reach the Key Vault.
  • 5. Least Privilege Always grant the minimum required permissions. This reduces security risk and improves governance.
  • 6. Verification After configuration, test the app by trying to fetch a secret. If access fails, review the role assignments or policy settings and adjust them accordingly.

In simple terms, you must give the app an identity, assign it permission in Key Vault, and make sure the access is limited to what it needs.

📊 Access Policies vs Azure RBAC

Feature Access Policies (Legacy) Azure RBAC (Recommended)
Scope Key Vault-specific Works across Azure resources
Granularity Limited permissions Fine-grained role-based control
Management Configured inside Key Vault Managed through Azure IAM and role assignments
Best Fit Simple, small setups Enterprise and scalable environments

🧭 RBAC Role Assignment Steps

  1. Enable identity for the application.
  2. Open the Key Vault and go to Access control (IAM).
  3. Choose Add role assignment.
  4. Select a role such as Key Vault Secrets User or Key Vault Administrator.
  5. Assign it to the application’s Managed Identity or Service Principal.
  6. Verify access and adjust permissions as needed.

🪪 Managed Identities

Managed identities let applications authenticate to Azure services without storing credentials directly in code.

System-assigned

Tied to one Azure resource and deleted with it.

User-assigned

Created as a separate resource and can be shared across multiple services.

Benefit

No secret handling in code and automatic credential management by Azure.

🚀 App Service Example

  1. Enable the App Service’s system-assigned managed identity.
  2. Grant the identity a Key Vault role such as Key Vault Secrets User.
  3. Use Azure SDKs in your application to fetch the secret.
using Azure.Identity;
using Azure.Security.KeyVault.Secrets;

var client = new SecretClient(
    new Uri("https://<your-keyvault-name>.vault.azure.net/"),
    new DefaultAzureCredential());

KeyVaultSecret secret = client.GetSecret("MySecretName");
Console.WriteLine(secret.Value);

When the app runs in Azure, DefaultAzureCredential can automatically use the Managed Identity to authenticate to Key Vault.
